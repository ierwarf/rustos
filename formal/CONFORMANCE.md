# TLA+ source-conformance audit

This is a source-level audit of the contracts modeled in this directory. It
checks that the Rust transition, identity, and cleanup boundary exists at the
named source anchor. It is not a claim that finite TLC exploration proves Rust
equivalence, CPU memory ordering, ELF/PE parser safety, or full scheduler CPU-time fairness.

## Executable cross-tool mappings

| Registered model | Additional executable evidence | Boundary |
| --- | --- | --- |
| runtime-control-rpc | `libs/runtime-control` test emits `rustos-formal-trace-v1`; `check-runtime-trace.py` independently replays `ReceiveResponse` and its `Classify` matrix | Six concrete source outcomes, not production telemetry or arbitrary socket interleavings |
| endpoint-publication | TLAPS proves `EffectiveEndpointRequiresRunningOwner`; Loom enumerates the lock/recheck versus exit/revoke proof kernel | The theorem is an unbounded definitional lemma and Loom is a mapped kernel, not a full-source equivalence proof |

| dual-abi-byte-parser and network-payload-session | Rust libFuzzer drives the shared ELF and Ethernet admission functions; Clang libFuzzer/ASan/UBSan includes and drives the exact DVM GPU C batch parser | Bounded smoke runs are bug finding, not exhaustive proof or a sustained corpus campaign |

## Discrepancies found and closed

1. `TRANSFER_OBJECTS` was owned by compat while endpoint removal and task exit
   occur in IPC runtime/process substrate. A handle-aware receive could dequeue
   descriptors, fail later user-output validation, and leave registry entries
   unreachable; caller exit also left queued request/reply descriptors alive.
   The registry now resides in `kernel-ps`; runtime returns detached descriptor
   batches, and compat/PS dispose of them on every terminal path.
2. `PROC_PREPARES` was owner-bound for authorization but had no owner-exit
   cleanup. A loader crash between `PREPARE` and `COMMIT` could retain bounded
   prepare slots and pinned mapping metadata. Both ordinary exit and
   signal-driven process termination now remove the owner's uncommitted state.
3. Exec authorization accepted any live TID without proving its requested PID,
   while cancel and exec-target removed tickets before comparing that pair. A
   malformed request could therefore authorize a mismatched target or destroy
   a valid ticket. Target-thread exit and exec sibling retirement also retained
   pending tickets/register handoffs, and the handoff was inserted after image
   replacement. Authorization now checks the exact live pair, removal follows
   comparison, transition insertion precedes replacement, and thread/process
   teardown purges target-bound ticket state.
4. `runtime-control` accepted any successful response opcode and negated every
   nonzero signed status. A stale/cross-RPC reply could therefore become a
   false launch/terminate success, while `i32::MIN` could overflow. Response
   identity and shape are now validated before success; server error envelopes
   retain their documented opcode-zero compatibility.

## Remaining boundaries outside this audit

- The signed post-cleanup QEMU capture source-matches the retired-path guards:
  GPU/display readiness followed only staged-copy GPU composition with explicit
  fences and three scanout buffers, and no legacy/direct-import or
  display-unavailable marker occurred. It remains performance-blocking rather
  than release evidence: the private proof reached 110.389 FPS, but settled
  relay samples were 50.730--59.105 FPS and WayClick was 35.894--41.776 FPS.
  uiserver cannot yet include aggregate Wayland/AF_UNIX readiness in its wait;
  the general cross-provider wait-set ABI is a separate required boundary.
- Public IPC calls intentionally retain blocking ABI semantics; only internal
  policy-service waits are deadline-bounded.
- The scheduler distribution model proves the one-System/one-User bounded
  reservation only. It does not prove multicore CPU-time distribution or
  hardware interrupt latency; target measurements remain release-blocking.
- ELF/PE byte parsing and page-table lifecycle now have finite abstractions and
  mapped source tests. Kani also proves the compositional decoder,
  segment/section, entry, single-relocation, and single-import contracts. Full
  multi-block corpus fuzz/native launches and target TLB behavior are
  independent release evidence and remain open.
- **Release-blocking hardware gap:** the supervised physical display-DVM source
  requires a non-identity QEMU IOMMUFD/VFIO address space, read-only display DMA,
  complete-group reset, and fail-closed revoke. Target fault/revoke/reset and
  guest-kernel captures are still absent. The separate RustOS native boot-device
  path also retains an identity-only kernel backend. Both remain failed gates;
  the source state machines and TLC runs do not substitute for hardware proof.
- No enabled topology advertises a trusted physical display or trusted
  human-input device. The trusted-UI model verifies the fail-closed admission
  rule and source provenance only; an in-band DVM display overlay cannot
  authenticate to a human, so privileged-prompt admission remains blocked.
